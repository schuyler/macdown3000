## Symboles et branches examinés

- Initialisation : destruction des anciens listeners, maintien conditionnel du panneau, consommation puis suppression des variables de configuration. Les données de configuration viennent de l’installation native, pas d’une conversion du DOM modifié.
- `listen`, `send`, `hide`, `draft`, `finish`, `commit` : jeton ajouté au transport, texte brut du brouillon, absence de transaction si texte inchangé, terminaison native après succès. Un refus conserve le brouillon ; la fermeture/sauvegarde native appelle le même validateur.
- `currentSelection` : sélection non réduite, frontières sur éléments ou nœuds texte, parcours de tous les runs, vérification des caractères non mappés et séparateurs uniquement entre blocs distincts. Le backend revalide offsets UTF-16, ordre et texte ; les attributs DOM ne fournissent aucune autorisation source à eux seuls.
- `selectionPayload`, `command` : repli sur sélection mémorisée uniquement pendant rendu ou focus interne au panneau ; changement de sélection souris purge la mémorisation. La queue native compare les anciennes bornes avant continuation.
- `button`, `select`, `createPanel` : activation conditionnelle tâches/code/math/barré, commandes autorisées, URL demandée puis validée nativement, CSS borné à la fenêtre, accessibilité et impression masquée. Le remplacement direct est interdit pour plusieurs runs et pour le code.
- `begin` et listeners des spans : remplacement du fragment entier explicitement choisi ; refus des retours source ; Escape annule, Enter valide, composition IME ignorée, `beforeinput` refuse les commandes de format HTML ; collage texte seul et retours aplatis, drop refusé. Aucune interprétation HTML de la saisie n’est faite par le panneau.
- `updateStyles` : intersection des ancêtres pour chaque run ; exceptions espaces du code alignées sur le contrat ; type de bloc commun ; aucun style partiel affiché actif. La fidélité source est assurée par le renderer et le validateur native, pas par cette indication visuelle.
- `updatePanel`, souris/sélection/blur/scroll/resize : délai clavier, verrou pendant déplacement souris, ouverture au relâchement, position bornée, focus panneau conservé, suppression de mémorisation en cas de vraie désélection. Le panneau reste pendant un rendu qui restaure la sélection.
- `showEditError`, `restoreSelection`, `normalizedSelectionText`, API publique et `destroy` : restauration exclusivement de runs ordonnés et texte concordant ; normalisation des séparateurs sans changer la source ; cleanup des timers/listeners et style selon rétention ; refus explicite et brouillons récupérables.

## Défaut confirmé JS-01

Après `showFormattingError()`, sélectionner un autre passage admissible conservait le message « Mise en forme refusée » du passage précédent. `showEditError` ajoutait le message sans contexte et `updatePanel` ne le supprimait jamais. Un nouveau rendu le supprimait indirectement, mais une simple nouvelle sélection ne déclenchait pas ce rendu.

Correction : rattacher l’erreur à la signature des runs et du texte de la sélection ; la mise à jour du panneau efface le message quand cette sélection change. Un scroll sur la même sélection conserve l’explication ; une désélection masque le panneau ; un brouillon actif garde son erreur de récupération.

Phase rouge confirmée par le parent dans `build/SquashedPreviewAudit/native-red.log` : assertion message absent après sélection B échouée. Phase verte : ce test réussit dans `build/SquashedPreviewAudit/native-stage-2.log` (1,028 s), qui conserve aussi un échec attendu distinct du compteur avant sa correction ; ne pas présenter le contrôle complet comme vert. Commit de correction et de régression : `7219b60`. Contrôle JS exécuté : `node --check MacDown/Resources/Extensions/preview-edit.js`, sortie 0.

Demande utilisateur distincte : bouton « Fermer » retiré dans `98966d7`. La désélection masque toujours le panneau, scénario vérifié par le test ci-dessus ; aucun changement de transaction Markdown. Le contrôle syntaxique réussit après retrait. Les contrôles de livraison ci-dessous doivent aussi couvrir cette version finale.

## Défaut confirmé JS-02 — identifiants DOM rédigés par l’utilisateur

Un document HTML admissible portant `id="macdown-preview-edit-style"` peut être pris pour la feuille de style du panneau : l’installation écrase alors son `textContent` avec le CSS. Un élément rédigé portant `id="macdown-preview-format"` peut aussi être retenu puis vidé lors d’une restauration. Les recherches globales du message d’erreur et les sélecteurs CSS sur ce seul ID partagent cette ambiguïté. Le code source du document n’est pas modifié, mais l’aperçu cesse de représenter son contenu.

Les attributs HTML rédigés `data-mp-edit-id` pouvaient également être interprétés comme des spans de mapping par les recherches DOM globales. Le validateur natif rejetait les faux identifiants sans corrompre la source, mais les indications de styles, la restauration ou le remplacement direct pouvaient viser le mauvais élément.

Correction appliquée : rétention et suppression par références DOM privées détenues par l’éditeur ; API `elements()` retournant `{panel, style, spans}` consommée par le remplacement natif de body et son scanner ; lookup des spans depuis le tableau réellement créé ; feuille de style visant une classe issue du jeton UUID du rendu ; message d’erreur privé au panneau. Les IDs restent des repères de diagnostic, jamais une preuve de propriété. Les sondes HTML hors DOM actif ne contiennent pas ces contrôles et ne doivent pas exclure un ID ou un attribut documentaire.

Régression réelle WebView `testPreviewControlsPreserveAuthoredIDsAndRunAttributes` : phase rouge exécutée dans `build/SquashedPreviewAudit/native-stage-3.log`, texte de DIV rédigé remplacé par le CSS et absence d’API privée attendus sur la version fautive. Le cas couvre trois IDs réservés et un attribut de run rédigé, puis une sélection réelle, transaction gras, rendu suivant, restauration et erreur privée en conservant les textes source et voisins. Phase verte initiale : `native-stage-4-green.log`, 10 tests / 0 échec, avec parcours d’intégration complet (62,815 s), collision (2,139 s), erreur et compteur. La seconde passe a ensuite confirmé une collision de propriété nommée : un DIV rédigé `id="macdownPreviewEditor"` exposait un élément DOM au lieu du contrôleur. `named-controller-red.log` reproduit l’absence d’installation (1 test, 2 échecs). Les appels initiaux et natifs vérifient désormais `typeof elements/destroy === "function"` avant de consommer le contrôleur ; ce DIV reste documenté et conservé dans la même régression. Phase verte finale de cette frontière : `identity-wrapper-green.log`, test collision réussi (2,265 s). Ce batch conserve trois échecs distincts de wrapper/undo et ne constitue pas une suite globalement verte. Les gates de livraison globales restent en attente. Contrôle syntaxique de la version finale : `node --check`, sortie 0.

Origine : le détournement des IDs panneau/style et des attributs de run existait dans le commit fusionné. Le nettoyage du message introduit par JS-01 rendait aussi atteignable la suppression d’un DIV rédigé avec l’ID du message au chargement ; cette régression intermédiaire de l’audit a été détectée par la nouvelle phase rouge et corrigée par la référence privée `errorMessage`. Aucun changement du source Markdown n’a été constaté dans ce scénario.

Le marqueur `data-mp-preview-ui` rattaché au jeton du rendu appartient à la correction distincte du compteur de mots pilotée par le parent (`9ea74f0`) : un ID rédigé seul ne justifie pas l’exclusion d’un texte documentaire. Régression réelle JS chargé dans WebView, `testPreviewFormattingControlsDoNotChangeDocumentTextCounts`, réussie dans `build/SquashedPreviewAudit/count-green.log` (1 test, 0 échec, préférences restaurées) ; cette garantie doit être rejouée sur la version finale des références DOM.

## Seconde passe

Hypothèses réexaminées : le focus du panneau ne doit pas déplacer la sélection source ; les anciens jetons sont refusés après rendu ; une désélection annule la queue ; un brouillon refusé reste récupérable ; les séparateurs interblocs n’octroient pas de style ; la destruction ne laisse pas d’anciens handlers actifs ; un nom d’attribut ou d’ID rédigé ne prouve jamais la propriété d’un contrôle. La rétention du panneau se fait dans le même remplacement synchrone de body, et sa reconstruction remplace ses enfants avant de rattacher les handlers. Les références des spans détachés ne sont pas utilisées : `mappedSpan` et `currentSelection` vérifient `isConnected`. Les nouvelles classes CSS ne visent que les spans et contrôles construits pour le jeton UUID courant. Aucun nouveau pipeline de conversion HTML vers Markdown n’est ajouté.

Limite explicitement examinée avec le lot Document : après saisie de ponctuation échappée, certains fragments ne restent pas littéralement mappables. Le contrat documente les fragments littéraux et le refus des correspondances non prouvées ; aucune modification incorrecte ni hypothèse déterminante n’a été établie. Cette limite reste visible, sans prétendre à un éditeur WYSIWYG complet. Les tests natifs et UI de livraison restent requis pour déclarer ce lot validé.
