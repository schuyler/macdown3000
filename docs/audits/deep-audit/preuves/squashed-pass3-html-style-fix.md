# P3-HTML-STYLE — inclure le thème sélectionné indépendamment de son adresse

Le parcours public exportHtml initialise stylesIncluded avec un cast NSString*→BOOL. Sur Intel BOOL est signed char : une vraie chaîne de préférence non nil dont l’adresse se termine par00 devient NO. Le checkbox du controller/XIB et HTMLForExportWithStyles consomment cette valeur ; la CSS du thème actif est omise, ou un clic destiné à décocher l’option l’inverse incorrectement. Le cast est déjà présent dans dbc6b23^ : défaut préexistant, pas produit par les corrections de cette passe.

Lecture fraîche de toutes les dépendances de cette chaîne : controller .h/.m et XIB, MPPreferences .h/.m, PAPreferences .h/.m, plus renderer export et document déjà relus. Getter réel NSUserDefaults, strings Foundation ordinaires retenues (borne1024, assertion si allocation recherchée absente), thème temporaire UUID, checkbox réelle, renderer/WebView et fichiers HTML réels ; seul NSSavePanel est contrôlé. Les préférences et le thème temporaire sont restaurés/nettoyés finally et le coffre vérifie leur restauration.

Une première commande fat avec destination x86_64 a passé : elle est conservée comme caractérisation contradictoire, sans la qualifier de RED ni preuve d’un process Intel. Le test instrumente ensuite uniquement architecture compilée, BOOL macro et octet bas, sans valeurs privées. **RED forcé ARCHS=x86_64** : Pass3/html-style-intel-forced-red.log, architecture=x86_64 / OBJC_BOOL_IS_BOOL=0 / lowByte=0, un test / quatre assertions en échec / sortie65 / coffre restauré. Cases sélectionné→CSS incluse, utilisateur décoche→CSS exclue, préférence nil→CSS exclue et source conservée.

Correction minimale : comparaison explicite htmlStyleName != nil. Même contrat de présence, même controller/binding et même renderer ; aucune substitution de pipeline ou thème par défaut. Le test d’export passe ensuite dans la suite native Intel réelle (log native-intel-full). Suites finales et empreintes : voir clôture de passe3 ; validation conditionnée à leur réussite.

Gates réussies : native-intel-full.log1476tests0échec (139,038s), macroprocess du test x86_64. Après ajout d’une assertion explicite exigeant la completion avant la garde, le même test final a été relancé sur Intel puis ARM : html-style-intel-final-green.log et html-style-arm-final-green.log, chacun1test0échec/exit0/restauration vérifiée.
