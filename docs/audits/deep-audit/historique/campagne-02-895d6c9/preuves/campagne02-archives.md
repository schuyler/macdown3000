# Archives actives et contenu caché

Deux archives binaires auparavant hors inventaire sont désormais ajoutées explicitement : `MacDown/Resources/Data/data.map` et `treats.map`. Lecture physique complète, décodage de tous les objets NSKeyedArchive, inspection des références/classes et de chaque contenu textuel interprété. La lecture ne consiste pas à traiter les octets d'une image comme des lignes de source.

`data.map` contient cinq objets : dictionnaire mutable, sa classe, clé `MoskyかわいいよMosky` et un PNG de 2892399 octets. L'image a été extraite temporairement et examinée visuellement ; c'est une photographie. Le consommateur réel `NSTextView.insertMappedContent` transforme cette clé en image Markdown en écrivant dans un répertoire temporaire unique. Ce parcours est actif et a été intégralement lu dans la catégorie et les utilitaires ; aucune charge exécutable trouvée dans le contenu décodé.

`treats.map` contient seize objets : nom `mosky`, dictionnaire de trois documents sélectionnés par date MMDD (`0214`, `0819`, `0314`), classes de dictionnaire/NSString avec représentation OC_PythonString et un `.DS_Store` de 6148 octets. Les trois documents sont intégralement lus : CSS statique de centrage, titres de fête/anniversaire, exemple Python dans un bloc clôturé et un lien Twitter explicite dans le document du 14 février. Le Python est du texte rendu, pas du code exécuté. Le consommateur `treat()` n'ouvre ces documents que pour les noms d'utilisateur ciblés et une fois par date ; le lien n'est pas ouvert automatiquement par ce consommateur. La clé `.DS_Store` est inaccessible au sélecteur MMDD, mais l'archive reste active ; aucune suppression du parcours n'est justifiée par son caractère personnel.

Les archives sont des ressources bundlées consultées par `MPGetDataMap`, pas un flux de désérialisation fourni par un utilisateur. Elles constituent des fonctionnalités dissimulées de type Easter egg, désormais documentées. Aucun comportement malveillant démontré ; les deux ressources sont désormais validées après consommation native du bundle Debug final : `NSKeyedUnarchiver` décode les classes historiques, `NSImage/CGImage` décodent le PNG 1500×1500 et les trois documents sont des chaînes UTF-8 valides. Source du consommateur de contrôle : `/var/folders/sl/qh_kc_kn1r732kw2tsj7z5xh0000gn/T/macdown-archives-native-cpcx94t8/consumer.m`, exécution réussie. Les APIs de production et tous les objets/textes ont été examinés ; aucun appel externe ou Easter egg déclenché sur les données personnelles du réviseur.
