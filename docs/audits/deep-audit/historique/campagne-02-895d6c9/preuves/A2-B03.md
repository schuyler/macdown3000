# A2-B03 — perte de demandes CLI concurrentes

Défaut antérieur à la campagne 01, confirmé sur les producteurs et le consommateur de la baseline e5a5c23. Les trois clés CFPreferences étaient remplacées par chaque invocation, puis lues/effacées séparément par l'application. Deux producteurs avant activation perdaient la première requête ; un producteur entre lecture et effacement perdait sa requête. Reproduction interprocessus sur une suite UUID, sans domaine utilisateur ; détails dans campagne02-build.md.

La correction utilise un seul protocole append/drain sur une file plist privée, verrou inode permanent commun à l'application et à la CLI. Une invocation regroupe fichiers, dossiers et données stdin dans une requête. Les données restent dans la file privée : plus de fichier stdin global temporaire. La CLI échoue avant lancement si la persistance échoue. Les types et chemins, la taille du plist, les erreurs d'E/S et les fichiers inattendus sont vérifiés avant modification de la file. Sauvegarde temporaire privée puis renommage atomique ; lecture/drain et ajout sont sérialisés par flock.

MainController lit la même file pour supprimer le document initial superflu et consomme les batches sur activation ou réouverture d'une application déjà active. Une conversion des trois anciennes clés vers cette file préserve les demandes présentes lors de la mise à niveau ; les clés ne sont effacées qu'après enregistrement réussi. Les trois anciennes API pending de MPPreferences et leurs producteurs ont été supprimés après recherche exhaustive de leurs références et migration de leurs tests. Aucun second pipeline d'ouverture ne subsiste.

Tests root effectivement exécutés :

- `python3 MacDownTests/BuildTools/command_queue_tests.py` : huit producteurs / trois consommateurs, 320 requêtes, union exacte des demandes sans doublon ni perte. stdin binaire avec NUL, entrée vide, invocation TTY sans args qui préserve le pending, snapshot suivi d'un producteur, corruption, taille limite, chemins/types invalides, FIFO, symlinks et refus d'écriture. CLI entière compilée avec fixtures limitées aux frontières parser/launch OS ; stockage et stdin réels.
- XCTest ciblé sur le build neuf `build/AuditCampaign02`, scheme MacDown : sept tests de MPMainControllerFolderTests, zéro échec. Workspaces réels avec nib/window, deux pipes Unicode, fichier réel avec attente bornée, activation puis réouverture sans double ouverture, dossier absent qui ne perd pas le pipe voisin, conversion legacy UUID et retry après échec de file corrompue.
- Résultat : `build/AuditCampaign02/Logs/Test/Test-MacDown-2026.10.07_22-48-35-+0200.xcresult`, log `/tmp/macdown-campaign02-command-tests.log` ; la présence de sept tests exécutés est vérifiée, pas seulement le code retour de xcodebuild.

XCTest a tourné dans un vault privé réversible : snapshot CF des trois domaines réellement concernés, mise à l'abri par renommage d'ApplicationSupport/cache/savedState et de la queue existante, HOME de fixture, arrêt du seul binaire de test connu, restauration finale et égalité des préférences vérifiée. Aucun processus d'application installée n'est arrêté par le wrapper. Neuf scénarios synthétiques de restauration ont précédé son utilisation.

Versions finales lues intégralement par root : header de queue, CLI, MainController, MPPreferences h/m, nouveaux runners et tests ; tests consommateurs relus après leurs derniers ajouts. Seconde passe : les tableaux legacy vides ne suppriment pas l'untitled, une pipe vide reste une demande valide, les erreurs de conversion conservent le pending, et une file déjà drainée ne rouvre aucun document.

Limites : le crash après drain et avant ouverture peut perdre le batch ; la conversion entre ancien stockage CF et nouveau plist n'est pas une transaction durable inter-stockages et peut être rejouée après un crash entre enqueue et effacement legacy. Aucune garantie exactly-once après crash/coupure machine. La compatibilité vise les demandes existantes lors de la mise à niveau, pas des producteurs anciens continuant à écrire après cette conversion. Les tests ne certifient pas encore l'élection LaunchServices d'une CLI packagée ; suite complète et gates de livraison encore ouvertes.
